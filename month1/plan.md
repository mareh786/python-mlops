# Month 1 Plan — DevOps to SDE/SRE Transition

## Objective of Month 1

The first month is about building the base correctly.  
Do not try to learn everything at once. The goal is to create discipline, strengthen coding basics, and start thinking like a software engineer instead of only an operations engineer.

By the end of Month 1, you should have:

- one primary programming language selected
- a daily coding habit
- basic understanding of time and space complexity
- confidence with arrays, strings, hashing, recursion, linked list, stack, and queue
- revision of core CS basics like OS, networking, and DB fundamentals
- the initial structure of one backend project
- a proper note-taking and progress-tracking system

---

## Main Focus Areas for Month 1

Month 1 should focus on four tracks running in parallel.

### 1. Coding and DSA Foundations
You need to start coding daily in one language.  
For your case, Python is the most practical option for interview preparation.

This month is not about solving very hard problems.  
It is about becoming comfortable with problem-solving patterns and writing code cleanly.

Topics to cover:
- Python basics revision
- time and space complexity
- arrays
- strings
- hash maps / dictionaries
- sets
- two pointers
- sliding window basics
- linked list basics
- stack
- queue
- recursion basics

---

### 2. Core Computer Science Revision
You do not need deep academic study in Month 1.  
You need practical, interview-relevant understanding.

Topics to cover:
- what happens when you type a URL in the browser
- process vs thread
- basic memory concepts
- basics of CPU, RAM, disk
- TCP vs UDP
- HTTP / HTTPS basics
- DNS basics
- ports
- SQL basics
- primary key, foreign key
- normalization basics
- indexing basics

---

### 3. Software Engineering Practice
This month you should begin shifting from scripts to software engineering style.

Topics to cover:
- project structure
- functions and modular code
- basic OOP concepts
- input validation
- error handling
- logging basics
- environment variables
- basic unit testing

---

### 4. Project Start
You should start one project in Month 1 itself.  
It does not need to be fully built this month, but the foundation must begin.

Recommended project direction:
- a small backend service related to DevOps/SRE workflows

Example ideas:
- service status tracker
- incident record API
- deployment log API
- internal health-check dashboard backend
- simple change request tracker

Minimum outcome for Month 1:
- choose project idea
- define features
- set up repository
- define folder structure
- create basic API skeleton
- add README draft

## Daily Study Structure for Month 1

You should keep the daily plan simple and repeatable.  
Do not overload yourself at the start.

A practical daily structure:

### Weekdays
- 60 to 90 minutes DSA and coding
- 30 to 45 minutes CS fundamentals
- 30 to 45 minutes project work

Total:
- around 2 to 3 hours daily

### Weekends
- 1 to 2 hours revision
- 2 to 3 hours project building
- retry old coding problems
- organize notes and mistakes

Total:
- around 3 to 5 hours daily if possible
